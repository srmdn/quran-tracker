# Decision Records

Use this directory to store architecture, security, and governance decisions.

## Naming Convention

`YYYY-MM-DD-short-title.md`

Example: `2026-03-28-csrf-protection-approach.md`

## When to Write One

- Security fixes that change authentication, authorization, or data handling (Tier 2+)
- Anti-cheat mechanisms with score consequences
- Architecture changes affecting the data model or auth flow
- Policy exceptions
- Post-incident corrective actions

Start from `docs/decisions/templates/decision-record-template.md`.
